The two servers

They are wired differently on purpose. bambu-studio is first-party and dependency-free — it drives the Mac, talks to Bambu's cloud, and shells out to Python. bambu-printer is a forty-line launcher: it reads your config, maps it onto the environment variables a community package expects, and hands the session over.

These tools belong to bambu-printer-mcp, fetched through npx at launch. The launcher's own job is narrow: find printer-config.json — an explicit path, your home directory, or a Cowork project folder — refuse to start if host, access code or serial is still a placeholder, and pass the rest through as environment.

From model file to plate

The prep skill's whole job is turning a file you downloaded into a plate you can look at and approve. The geometry work happens in one Python script with no dependencies for inspection — numpy and matplotlib come in only for previews.

  1. InspectList every part with real dimensions, straight from the mesh — no dependencies needed.python3 model_tools.py inspect model.3mf

  2. RenderA labelled preview so "the base" means the same piece to both of you.… render model.3mf --out preview.png

  3. ExtractPull only the parts you named into a clean file, scaled, laid flat and arranged on the bed.… extract model.3mf --parts "base" --scale 0.2 --lay-flat --out plate.3mf

  4. Name itProject name, description, designer credit and embedded pictures — also exposed as get_project_info / set_project_info.… project plate.3mf --set-name "Hive base"

  5. Load itThe plate opens in Bambu Studio with your own presets. The last click is yours.

The line it doesn't cross

Never start, queue or resume a print, and never heat the nozzle or bed.

The rule is written into the watch skill, not just into the code: Claude checks and reports, you press Print plate. No print-start or upload tool is called even when one is available.

This is what lets the printer stay in normal cloud mode. No Developer Mode, no unlocked LAN control, and the Bambu Handy app keeps working alongside it — status reads and camera frames are all the plugin ever asks for.

Where it's fragile

  • No official API. Sign-in and sync follow Bambu's cloud endpoints as documented by the OpenBambuAPI community project. Bambu can change them at any time.
  • Firmware keeps tightening. Snapshots and status work in cloud mode on current firmware, but behaviour varies by model. Control calls may come back with auth errors such as 84033543 — expected, and not retried in a loop.
  • Plain 3MF, by design. Files the prep skill writes carry geometry only, so Studio notes they're "not from Bambu Lab" and applies your current presets.
  • Cameras differ. A1 and P1 use the TCP-6000 path with no extra tooling; X1 and H2 need ffmpeg installed.
